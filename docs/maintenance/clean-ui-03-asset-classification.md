# P5 — evidence-based asset classifications

Use `node tools/audit-repository-assets.mjs` from the repository root. The report now classifies every discovered asset into **literal-reference**, **dynamic-or-catalogue**, or **unresolved**. A literal reference is source-text evidence only; flags, crests and division art rely on dynamic/generated paths, while all other candidates without literal mentions remain unresolved. **None is considered genuinely unused.** The `provenUnused` array deliberately stays empty because no runtime, generator, manifest and publication-safe deletion proof has been established. Historically retained resources cannot be identified from this inventory alone and remain unresolved pending provenance evidence. No asset removal is authorized. This closes classification as an evidence/unknown labeling exercise only, and does not satisfy the separate existing P5 removal checkpoint.

## Evidence categories (2026-10-27)

**Directly referenced:** pathname literal found in repository source (not proof of runtime exercise). **Generated/dynamic:** flag SVG names are calculated by `flagForCountry` in `tools/generate-app-pages.mjs`; club crest references flow through `clubCrestAssets()` / generated manifests and runtime crest host enhancement; division artwork is resolved by generator. **Retained/provenance:** flag upstream license inventory is recorded in `assets/flags/SOURCE.md`; this must be preserved. **Unresolved:** no literal reference and insufficient dynamic/provenance/runtime evidence. **Genuinely unreferenced and safe to remove:** no confirmed entries. The classification task can finish with an explicitly unknown bucket; *removal* cannot.
