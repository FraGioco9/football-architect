# I03 reversible shared DOM renderer — implementation boundary

Added an isolated DEV-only shared presenter that uses the existing `faStandingsView.createRow`, `faStandingsMobile.prepare`, and `faFixtures.prepare/snapshot` APIs. It prepares all sixteen standings rows, mobile rows and regular-season fixtures before touching mounted DOM. The commit step applies these changes together; rollback restores the previous desktop/mobile DOM and fixture snapshot. A controller listens for validated presentation events, with a **third deliberate opt-in** `data-fa-i03-renderer="1"` (never inserted by the DEV server), cancels presentation on route/debug/source invalidation, and emits commit/failure events.

**Not a finished end-user integration:** postseason display is not yet transacted; form tooltip handlers on generated rows need the full shared binding lifecycle; contextual season data is not committed here; international and club/calendar consumers remain absent. For these reasons the renderer gate is intentionally never set by the site, and no existing Debug UI changes. Do not turn it on for regular manual QA until the shared presenter contract is complete and I06 verifies rollback, first paint, promotion/relegation, accessible form and mobile/fixtures consistency. No public bundling or remote dependencies.
