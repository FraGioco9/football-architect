# #613 — Single-result-engine clean break

**Owner decision 2026-11-16:** no backward compatibility for the score-only simulator. Replace the old simulator, day evidence and reader/replay chain as one reviewed cutover. No dual authority, season pin, old-result adaptation or legacy fallback.

## Scope of this Draft/HOLD PR
- One deterministic engine `temporary-lineup-v1` for all four roster modes, **including fallback-vs-fallback**. A team with fewer than 11 real eligible players gets neutral strength 61 and unattributed team goals. No fabricated player appearances.
- Real 4-3-3 XI whenever 11+ eligible affiliated players exist, with frozen attributes, player IDs, goals, minutes, extra time and penalties.
- One immutable per-match receipt. Read history from that receipt, never from a player's current contract.
- One V2 day envelope for all completed and even empty days, `season_lineup_day_outcomes` (migration 0029 in branch), containing only immutable references, results and receipt hashes. This is the **only intended** daily authority; old tables are unused after cutover.
- Verified due-fixture set comes from the canonical sporting progression, not a caller-controlled HTTP list. The daily evidence builder validates exactly-once match receipts and hashes the sorted payload; replay must validate the same frozen match receipts.

## Subsequent required integrated cutover
1. Integrate the new engine into `processSportingDay` through an authenticated day-finalization roster snapshot. Ensure no future-day results are generated by calendar publication; if prior administrative days require sporting evidence, process each elapsed day at the correct lifecycle point.
2. Replace old `season_day_outcomes` writes and validations in `lifecycle-command.ts`, `admin-calendar-publish.ts`, `admin-calendar-advance-plan.ts`, and other writers **with one new V2 table**. Save every match receipt, knockout plan, V2 day row, world update and audit in a single guarded D1 transaction.
3. Replace legacy reconstruction in `public-sporting-read.ts`, `public-match-read.ts`, season archives, standings/qualification. Validate complete V2 evidence from persisted receipts, not by resimulating against today's roster.
4. Update fresh-world tests/fixtures and remove the obsolete score-only modules and tables when a separately authorized development database rebuild/cutover is arranged. Avoid any in-place remote deletion without explicit permission.
5. CI exact-head, full local Worker D1 rollback and replay, end-to-end QA, then separate authorization for merge, remote migration/deployment and data reset.

**Important:** The presence of the new 0028/0029 migrations on a branch does NOT authorize executing them. This PR remains Draft/HOLD until the entire official writer/reader switch is reviewed. Existing live results are untouched.
