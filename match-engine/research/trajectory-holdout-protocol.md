# ME-PHYS-15 — Independent 3D flight evaluation protocol

**Status: draft diagnostic protocol / no authentic licensed holdout acquired.** Scope: Football Architect issue #452, PR #455 Draft/HOLD. This document does not grant commercial-use rights, declare that a specific ball is calibrated, change physics-v4, or authorize merge/deploy/D1.

## Minimum observations before quantitative scientific review

An external source must document one verified physical ball specimen and its provenance; independently measured initial position, velocity and **angular velocity**; ball-center coordinates in metres; a known shared right-handed or explicitly transformed XYZ frame and clock origin; triangulation error/uncertainty; contact/occlusion flags; separate original acquisition sessions; and explicit permission for the intended research/game use. Treat absence of any of these as an explicit limitation, not an inferred measurement.

Use whole kick/session groups for calibration versus holdout, never random per-frame splitting of the same trajectory. Never use measurements generated by the model under evaluation as an independent holdout. The current Soccer Ball 3D reference is **not** documented as the same Trionda specimen and its annotations are non-commercial; no raw dataset has been downloaded, committed, redistributed or evaluated here.

## Numerical contract

`src/trajectory-validation.mjs` provides:

```js
evaluateFlightTrajectory({
  observed: [{timeS: 0, xM: 0, yM: 0, zM: 1}, ...],
  predicted: [{timeS: 0, xM: 0, yM: 0, zM: 1}, ...],
  maxGapS: 0.05,
  coordinateConvention: 'unverified'
})
```

The arrays must be separate, ordered, finite, contain at least two observations and cover one continuous track each. Predicted timestamps must cover all observed timestamps. Linear interpolation at observed times is allowed only between neighboring predicted states within `maxGapS`, without extrapolation. The numerical output reports a per-observation 3D absolute distance, overall 3D MAE/RMSE, per-axis RMSE, maximum absolute and endpoint distance and RMSE of **displacements relative to each series' first observed timestamp**. If the two origins differ only by a fixed translation, absolute errors remain nonzero while relative-displacement errors may be zero. This does not align unknown coordinate axes, timestamps, scales, camera extrinsics or non-identical physical flight conditions.

`generateDisposableBallPrediction(RAPIER,createEngine,{scenario,options,seconds})` makes a **new disposable 60Hz world**, returns 3D **ball-center** positions and disposes it. It does not touch an active LAB world or introduce new gameplay physics. Default scenario and optional aerodynamics follow existing restricted diagnostic rules.

## Acceptance and non-acceptance

Numerical software acceptance: exact synthetic self-comparison RMSE near zero, explicitly known origin shift, small controlled synthetic drift, deterministic Rapier reset, no mixed track IDs, no nonfinite values, strictly increasing timestamps, no extrapolation and bounded interpolation gaps.

**Not accepted by these tests:** scientific coefficient calibration, uncertainty intervals, measured spin, source authentication, data rights, independence of real flight measurements, validated contact event timing, or any gameplay coefficient activation. Every evaluation report remains `scientificVerificationComplete:false`, `licensePermissionVerified:false`, `approvedForGameplay:false`, irrespective of achieved numeric error or manually supplied coordinate-frame labels.

**Future release gate:** independently authenticated same-specimen Cd(v) and signed Cs/Cl(v,spin,axis), measurement uncertainties and spin decay, legally reusable whole-session 3D trajectories, independently established pre-contact windows and frozen acceptance thresholds defined **before** looking at the held-out results. Only a separate owner-approved change may select a universal gameplay aerodynamic model and new replay version.
